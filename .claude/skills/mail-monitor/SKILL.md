# mail-monitor — 지원사업·수출 공고 모니터 실행 스킬

## 이 스킬이 하는 일 (쉬운 말)

repo 루트의 `monitor.py` 는 정부·지자체 지원사업/수출 공고를 여러 사이트에서 자동으로 모아,
중복·날짜·팀별 키워드로 걸러내고, AI로 요약한 뒤, 팀별 수신자에게 메일로 보내는 프로그램이다.
**로직은 전부 monitor.py 안에 이미 들어 있다.** 이 스킬은 그 프로그램을
**올바른 명령/모드로 대신 실행해 주고, 나온 결과를 사람이 알아듣게 풀어 보고**하는 얇은 안내자다.

핵심 안전 규칙: **기본은 "미리보기"** 다. 미리보기는 공고를 다 모아 누구에게 무엇이 갈지 보여주기만 하고
**메일은 한 통도 보내지 않는다.** 진짜 발송은 사용자가 "보내" 라고 그 자리에서 분명히 말했을 때만 한다.

## 언제 이 스킬이 켜지나 (트리거)

- "오늘 공고 뭐 떴어", "공고 확인", "지원사업 모니터 돌려줘", "메일 모니터", "공고 미리보기", "dry run"
- "메일 보내줘", "공고 발송해줘" → **실발송 의도. 반드시 한 번 더 확인 후 진행** (아래 안전장치 참고)
- "누가 받아?", "수신자 점검", "어떤 사이트에서 수집돼?", "발송 설정 확인"
- "이 키워드 놓치지 마", "집중 모니터링에 추가", "워치리스트 추가" (특정 공고를 절대 안 놓치게 강조)

단순한 질문("monitor.py가 뭐야?")은 스킬 없이 바로 답해도 된다.

## ⓪ 시작 전 30초: 지금 환경에서 무엇이 되는지 먼저 확인한다

`monitor.py` 는 **import 하는 순간** 아래 4개 환경변수를 요구하고, 하나라도 없으면 즉시 죽는다
(`--help` 조차 안 된다). 이 값들은 `.env` 에 들어 있고 `.env` 는 git 에 올라가지 않는다.

| 필수 환경변수 | 쓰임 |
|---|---|
| `BIZINFO_API_KEY` | 기업마당 공고 수집 |
| `ANTHROPIC_API_KEY` | 공고 AI 요약 |
| `GMAIL_ADDRESS` · `GMAIL_APP_PASSWORD` | 메일 발송 |

그래서 **모드별로 되는 환경이 다르다.** 아무거나 실행하기 전에 이걸 먼저 판정하라:

```bash
test -f .env && echo "ENV_OK: 전 모드 사용 가능" || echo "ENV_NONE: C·D 모드만 사용 가능"
```

| 환경 | A 미리보기 | B 실발송 | C 설정점검 | D 워치리스트 |
|---|---|---|---|---|
| **로컬 PC** (`.env` 있음) | ✅ | ✅ (승인 필요) | ✅ | ✅ |
| **클라우드 세션** (`.env` 없음) | ❌ 즉시 실패 | ❌ | ✅ | ✅ |

`ENV_NONE` 인데 사용자가 A·B(수집·발송)를 요청하면 **실행을 시도하지 말고** 이렇게 알린다:
> 이 환경에는 API 키(.env)가 없어 수집·발송은 돌릴 수 없습니다. 설정·수신자 점검과 워치리스트 편집은 가능합니다.
> 수집·발송은 로컬 PC(D:\mail)에서 실행해 주세요.

**비밀값(주소·앱 비밀번호·API 키)은 어떤 경우에도 화면에 출력하지 마라.**

## 진행 절차: ① 트리거 판별 → ② 모드 선택·실행 → ③ 결과 해석·보고

### ① 어떤 모드인지 먼저 정한다

| 사용자가 말한 것 | 모드 | 메일 발송 |
|---|---|---|
| "확인 / 미리보기 / 뭐 떴어 / dry run / 돌려봐" | **A. 미리보기** (기본값) | ❌ 안 함 |
| "보내 / 발송해 / 메일 쏴" + 그 자리 승인 | **B. 실제 발송** | ✅ 함 |
| "누가 받아 / 수신자·설정 점검 / 사이트 목록" | **C. 설정 확인** | ❌ 안 함 |
| "이 키워드 놓치지마 / 워치리스트 추가" | **D. 집중 모니터링 추가** | ❌ 안 함 |

애매하면 **A(미리보기)로 처리**한다. 발송은 의심스러우면 하지 않는다 — 한 번 보낸 메일은 되돌릴 수 없기 때문이다.

> 실행 위치: 모든 명령은 **repo 루트**에서 돈다(로컬은 `D:\mail`). 설정 파일은 루트가 아니라
> **`config/` 폴더** 안에 있다. 파이썬은 리눅스/클라우드에서 `python3`, Windows 에서 `python` 을 쓴다.

### ② 모드별 실행

#### A. 미리보기 (발송 차단 — 기본값, 가장 자주 씀) · `.env` 필요

`--dry-run` 플래그가 발송과 seen_ids(이미 보낸 공고 기록) 저장을 **둘 다 막는다.** 안전하다.

```bash
python monitor.py --dry-run
```

네트워크를 아끼고 싶거나(사이트별 순차 수집 생략) 빠르게만 보고 싶으면:

```bash
python monitor.py --dry-run --skip-coverage-fetch
```

실행이 끝나면 `logs/` 폴더에 보고서 3개가 생긴다 (③에서 해석):
- `site_collection_coverage_report.md` — 사이트별 수집 현황
- `today_notice_missing_risk_report.md` — 오늘 공고 누락 위험
- `review_queue_YYYYMMDD.md` — 날짜 불명이라 빠질 수 있는 공고 목록

#### B. 실제 발송 (사용자가 그 자리에서 승인했을 때만) · `.env` 필요

**플래그 없이** 그냥 실행하면 진짜 메일이 나간다(`main()` → 실제 SMTP 발송 + 발송 기록 저장).

```bash
python monitor.py
```

발송 전 반드시: (1) 먼저 A(미리보기)를 돌려 "누구에게 몇 건이 갈지" 사용자에게 보여주고,
(2) "이대로 실제로 보낼까요? 보낸 메일은 취소할 수 없습니다" 라고 묻고,
(3) 사용자가 분명히 "보내" 라고 답한 뒤에만 위 명령을 실행한다.

> **테스트로 "나에게만" 1통 보낼 때 (중요):** 그냥 `python monitor.py` 를 돌리면 raw_all·watchlist 뿐 아니라
> **그룹(예: "경기 고양시")이 공고에 매칭되면 그 그룹 수신자(타인 포함)에게도** 메일이 나간다.
> `config/settings.json` 의 raw_all_recipients 만 바꾸는 것으로는 막지 못한다(실제로 한 번 타인에게 발송된 적 있음).
> 모든 발송 경로를 한 주소로 강제하려면 `--only-to` 를 쓴다:
> ```bash
> MONITOR_NO_PERSIST_SEEN=1 python monitor.py --only-to ekth3691@gmail.com
> ```
> (Windows PowerShell 은 `$env:MONITOR_NO_PERSIST_SEEN="1"` 를 앞줄에 따로 쓴다)

#### C. 설정·수신자 점검 (발송 안 함) · **`.env` 없어도 됨 → 클라우드 가능**

설정 파일은 전부 `config/` 안에 있고 git 에 커밋되어 있으므로, 어떤 환경에서든 그냥 읽으면 된다:

- `config/settings.json` — 날짜 필터 on/off, 며칠 전까지 볼지(`days_back`), 전체수신(raw_all) 수신자
- `config/groups.json` — 팀(그룹)별 키워드·지역·점수기준·**수신자(recipients)**
- `config/sites.json` — 어떤 사이트를 수집하는지(`enabled: true` 인 것만 수집)
- `config/watchlist.json` — 집중 모니터링 키워드/URL (아래 D)

수집 소스가 몇 개 켜져 있는지 같은 집계는 파일을 직접 세면 된다:

```bash
python -c "import json;s=json.load(open('config/sites.json',encoding='utf-8'));v=s if isinstance(s,list) else s.get('sites',[]);print('전체',len(v),'/ 켜짐',sum(1 for x in v if x.get('enabled')))"
```

`.env` 가 있는 로컬에서는 도우미 스크립트로 사람이 읽기 쉬운 요약을 뽑을 수 있다
(monitor 를 import 하므로 **클라우드에서는 실패한다**):

```bash
python scripts/monitor_dry_run.py          # 사람이 읽는 요약
python scripts/monitor_dry_run.py --json   # JSON 요약만
```

#### D. 집중 모니터링 추가 · **`.env` 없어도 됨 → 클라우드 가능**

`config/watchlist.json` 에 키워드나 게시판 URL을 넣으면, 그 공고는 날짜·그룹 필터를 **우회해 강제로 포함**되고
전용 메일(🎯)과 폰 푸시로 강조된다. 추가는 이 파일을 편집하는 것이 전부다.

구조 (`config/watchlist.json`):
```json
{
  "keywords": ["혁신바우처", "수출바우처", "IP나래"],
  "urls": ["https://pms.ripc.org/pms/biz/smallBusiness/"],
  "recipients": ["ekth3691@gmail.com"]
}
```

- `keywords`: 제목·내용에 이 단어가 있으면 강조 (영문 키워드는 단어 단위로 정확히 매칭)
- `urls`: 이 게시판/공고 주소에서 나온 공고는 무조건 포함
- `recipients`: 집중 모니터링 전용 메일을 받을 주소 (비우면 전체수신 주소로 감)

추가 후 `.env` 가 있는 환경이면 **A(미리보기)를 한 번 돌려** 그 키워드가 실제로 잡히는지 확인하고 보고한다.
클라우드처럼 실행이 안 되는 환경이면 "편집은 반영됐고, 실제 매칭 확인은 로컬에서 미리보기 1회 필요" 라고 알린다.
편집은 기존 항목을 지우지 말고 **새 항목만 덧붙이는 식**으로 한다 (사용자 설정 보존).

### ③ 결과를 사람 말로 해석해 보고한다

실행 후 화면 로그 끝에 이런 요약이 나온다. 이걸 그대로 붙이지 말고 **뜻을 풀어** 보고한다:

| 로그 항목 | 쉬운 뜻 |
|---|---|
| `collected` | 사이트에서 모은 전체 공고 수 |
| `new_items` | 그중 처음 보는(아직 안 보낸) 공고 수 |
| `final_mail_target_count` | 실제로 메일에 담길(=조건 통과한) 공고 수 |
| `date_review_queue_count` | 날짜가 불분명해 빠질 수 있는 "확인 필요" 공고 수 |
| `mail_sent` | 메일을 실제로 보냈는지 (미리보기면 False) |
| `seen_ids_persisted` | "보냄" 기록을 저장했는지 (미리보기면 False) |

보고에 꼭 담을 것:
1. **모드** (미리보기인지 실발송인지) — 맨 앞에 명확히.
2. **선별된 공고**: 몇 건이 어느 팀에게 갈지. 가능하면 제목 몇 개를 예시로.
3. **누락 위험**: `logs/today_notice_missing_risk_report.md` 의 "위험도 높음" 항목이 있으면
   "이건 자동에서 빠질 수 있으니 직접 확인하세요" 라고 짚어준다.
4. **메일 발송 여부**: 미리보기면 "메일은 보내지 않았습니다(미리보기)" 라고 분명히.

자세한 표는 `logs/` 의 .md 파일을 열어 핵심만 요약한다. 전체를 다 붙이지 않는다.

## 안전장치 (반드시 지킴)

- **기본은 미리보기.** 의도가 애매하면 발송하지 않고 `--dry-run` 으로 돈다.
- **실발송은 명시적 승인 1회 필수.** "보내줘" 한마디만으로 바로 보내지 말고,
  미리보기 결과(수신자·건수)를 보여준 뒤 "정말 보낼까요?" 를 묻고, 승인받은 직후에만 플래그 없는
  `python monitor.py` 를 실행한다.
- **비밀값 절대 출력 금지.** Gmail 주소·앱 비밀번호·API 키(`.env` 안의 값)는 화면에 찍지 않는다.
  수신자 이메일을 보고할 때도 필요하면 일부를 가린다(예: `ekt****@gmail.com`).
- **설정 파일은 최소 변경.** `config/watchlist.json` 등은 새 항목만 덧붙이고 기존 사용자 설정을 지우지 않는다.
- 발송 결과 메일이 0통이거나 실패가 있으면 그 사실을 숨기지 말고 그대로 보고한다.
- **여러 세션이 이 repo 를 동시에 만진다.** 파일을 고치기 전 `git status --short` 와
  `git ls-files --deleted` 를 먼저 본다.

## 비개발자용 사용 예시

**예시 1 — "오늘 공고 뭐 떴는지 보여줘" (미리보기, 안전 / 로컬에서)**

1. PowerShell 에서 `D:\mail` 로 이동한 뒤 실행:
   ```bash
   python monitor.py --dry-run
   ```
2. 끝나면 이렇게 보고한다:
   > 미리보기로 돌렸습니다(메일은 보내지 않았습니다). 오늘 총 42건을 모았고, 그중 새 공고 9건이
   > 조건을 통과해 메일에 담길 예정입니다. "인천 화장품팀" 5건, "서울 AI·SaaS팀" 4건.
   > 날짜가 불분명해 빠질 수 있는 공고가 2건 있으니 `logs/today_notice_missing_risk_report.md` 확인을 권합니다.
   > 실제로 보낼까요?

**예시 2 — "이 키워드 놓치지 마" (집중 모니터링 추가 / 클라우드에서도 가능)**

1. `config/watchlist.json` 의 `keywords` 에 사용자가 말한 단어를 덧붙인다(기존 건 유지).
2. `.env` 가 있으면 미리보기로 잡히는지 확인:
   ```bash
   python monitor.py --dry-run --skip-coverage-fetch
   ```
3. 보고:
   > 집중 모니터링에 "○○" 키워드를 추가했습니다. 앞으로 이 단어가 들어간 공고는 날짜·팀 필터와 상관없이
   > 무조건 포함되고 🎯 표시로 강조됩니다. 방금 미리보기에서 매칭 1건을 확인했습니다.
