# coverage_alert.py — 수집 이상 탐지

> **한 줄 요약:** "평소 N건 수집되던 사이트가 오늘 0건이면 경보를 울립니다."

---

## 이 모듈이 하는 일 (비유)

**매장 재고 관리 시스템**과 비슷합니다.

어느 매장에서 하루에 평균 10개씩 물건이 들어오던 곳이,
어느 날 갑자기 **0개**가 들어오면 "무슨 문제가 생겼나" 확인이 필요합니다.

이 모듈은 그 역할을 합니다:
- 각 사이트의 **평소 수집 건수**를 기록해두고
- 오늘 수집 건수가 **급감하거나 0건**이면 경보를 보냅니다
- **사이트가 고장났는지, 공고가 정말 없었는지** 구분합니다

---

## 핵심 개념

### 베이스라인 (기준선)
각 사이트의 **과거 수집 건수 이력**입니다. 예:
```
기업마당: [120, 115, 108, 125, 110] → 평균 약 116건
K-Startup: [15, 12, 18, 14] → 평균 약 15건
```

### 판정 기준
| 상황 | 판정 | 알림 |
|---|---|---|
| 오늘 0건 + 베이스라인 있음 | **수집 실패** | 🔴 즉시 경보 |
| 오늘 N건 + 베이스라인 대비 50%↓ | **급감** | 🟡 주의 |
| 오늘 N건 + 베이스라인 범위 내 | **정상** | ✅ 알림 없음 |
| 첫 실행 / 신규 사이트 | **판정 불가** | ⚪ 알림 없음 |

---

## 핵심 함수

| 함수 | 하는 일 |
|---|---|
| `load_coverage_baseline()` | 과거 수집 이력 로드 |
| `save_coverage_baseline()` | 오늘 수집 결과를 이력에 추가 |
| `_representative()` | 과거 이력의 대표값(평균/중앙값) 계산 |
| `_coverage_risk_level()` | 수집 건수로 리스크 레벨 판정 |

---

## 보수적 설계 (오탐 방지)

1. **베이스라인이 있을 때만 비교** — 첫 실행/신규 사이트에서는 절대 경보 안 울림
2. **수집 실패한 날은 이력에 안 넣음** — 장애 이력이 베이스라인을 오염시키는 것 방지
3. **양수 이력을 우선** — 0건 장애 이력이 있으면 대표값이 낮아지는 것 방지

## monitor.py와 연결

`execute_monitor()`가 수집을 마친 뒤, `run_coverage_anomaly_check()`를 호출해
각 사이트의 수집 상태를 점검합니다. 이상이 있으면:
- **폰 알림** (`alert_ntfy()`) — 빨리 확인하도록
- **경고 메일** (`alert_email()`) — 상세 기록
- **리포트 파일** — 나중에 분석용
