# monitor.py — 핵심 모니터링 엔진 (상세판)

> **한 줄 요약:** 인터넷에서 공고를 모아 우리 회사 것만 골라 메일로 보내는 전체 흐름을 지휘합니다.

---

## 이 파일이 하는 일 (비유)

**백화점 MD(Merchandiser)**처럼 동작합니다:

1. **거래처(사이트)에 전화**해서 "새 상품(공고) 목록 줘" (수집)
2. 받은 목록에서 **가짜·이미 본 것 걸러냄** (중복제거·기존 이력 비교)
3. 우리 매장 기준(그룹 조건)에 맞는 것만 **진열대에 올림** (필터링)
4. **메일로 카탈로그** 만들어서 고객(수신자)에게 보냄 (발송)

## 핵심 함수 상세

### 🔴 전체 흐름 지휘

#### `execute_monitor()` (라인 5421) — 심장

이 함수가 **전체 7단계를 한 번에 실행**합니다:

```
① fetch_all()          → 20개 사이트에서 병렬 수집 (8개 스레드)
② dedup_items()        → 같은 공고 중복 제거 (주관기관 버전 우선)
③ seen_ids 비교         → 이미 보낸 공고 제거
④ enrich_items()       → 상세 페이지에서 기간·지역·지원금액 추가
⑤ 날짜 필터             → 오늘 것만 (어제 영업일 기준)
⑥ 그룹별 필터링         → 각 수신자 그룹 조건에 맞는 것만
⑦ 메일 발송/초안 생성    → Claude AI 요약 후 발송
```

**파라미터:**
- `allow_send=True` → 실제 메일 발송
- `draft_mode=True` → Gmail 초안함에 저장 (실제 발송 안 함)
- 둘 다 False → **미리보기만** (로그에 결과 출력)

#### `main()` (라인 5764) — 명령어 출발점

```
python monitor.py --send --persist-seen    ← 실제 발송
python monitor.py --draft                  ← 초안 생성
python monitor.py                          ← 미리보기만
```

### 🔴 사이트별 수집 (20개)

#### `fetch_all()` (라인 3418) — 병렬 수집

- `ThreadPoolExecutor(max_workers=8)`로 **8개 사이트를 동시에** 수집
- 각 사이트의 `type`에 맞는 수집기를 `FETCHERS` 딕셔너리에서 찾아 호출
- 실패해도 다른 사이트에 영향 안 줌 (예외 처리)

#### `fetch_bizinfo()` (라인 1845) — 기업마당

- **직결 API** (`bizinfo.go.kr`) 시도
- 실패 시 **data.go.kr 폴백** (공공데이터포털)
- 한국 정부 사이트의 legacy SSL 문제 대응 (3단계 SSL 폴백)

#### `fetch_html_generic()` (라인 2049) — 범용 HTML

- `sites.json`에 `type: "html_table"` 또는 `type: "html_card"`로 등록된 사이트
- 페이지에서 **테이블 또는 카드**를 자동 감지해서 공고 추출
- **페이지네이션 자동 순회** (다음 페이지 있으면 계속)

#### HTTP 헬퍼

| 함수 | 역할 |
|---|---|
| `_http_get()` (1554) | GET 요청 + **3단계 SSL 폴백** (표준→검증해제→legacy) |
| `_soup()` (1584) | HTML을 BeautifulSoup으로 파싱 + SSL 폴백 + 재시도 |
| `_item()` (1617) | 아이템 생성 유틸 (표준 형식으로 감싸기) |

**3단계 SSL 폴백이란?**
한국 정부 사이트가 구버전 SSL을 쓰는 경우가 많아서:
1. **표준 검증** (정상 사이트는 여기서 성공)
2. **검증 해제** (인증서 문제 우회)
3. **legacy SSL 컨텍스트** (OpenSSL 3.x 호환)

### 🔴 필터링 — `evaluate_notice()` (라인 4338)

이 함수가 **"이 공고를 보낼지 말지" 최종 판단**합니다. 10가지 검사를 한번에:

```
1. 제외 키워드 검사     → "설명회·매뉴얼·지침" 같은 비공고 키워드 있으면 제외
2. 제목 앵커 검사       → "기관소개·정보공개" 같은 비공고 정적 페이지 제외
3. 서비스 키워드 검사    → "설명회" 단독이면 제외, 신청 가능하면 통과
4. 대상 유형 검사       → 공급자/수요기관/선정기업 구분
5. 마감 상태 검사       → 마감 지난 공고 제외
6. 지역 검사           → 우리 지역 아닌 공고 제외
7. 키워드 매칭          → 우선 키워드·일반 키워드 히트
8. 지원유형 매칭        → 투자·지원금·컨설팅 등 구분
9. 소스 우대           → 특정 소스(기업마당 등)는 무조건 포함
10. 스마트공장 예외      → 스마트공장 관련 설명회도 포함
```

**판정 결과 (`reason_codes`):**

| 코드 | 의미 | 결과 |
|---|---|---|
| `CLOSED_DEADLINE` | 마감 지난 공고 | ❌ 제외 |
| `REGION_NOT_ELIGIBLE` | 우리 지역 아님 | ❌ 제외 |
| `DISTRICT_NOT_ELIGIBLE` | 우리 구 아님 | ❌ 제외 |
| `GUIDELINE_OR_MANUAL` | 지침·매뉴얼 | ❌ 제외 |
| `INFO_SESSION` | 설명회 | ❌ 제외 (단, 스마트공장 예외) |
| `NOT_GRANT_NOTICE` | 지원공고 아님 | ❌ 제외 |
| `LOW_PRIORITY_SERVICE_KEYWORD` | 낮은 우선도 서비스 | ❌ 제외 |
| 없음 | 적합 | ✅ 통과 |

### 🔴 메일 작성·발송

#### `render_all()` (라인 4721) — 메일 본문 생성

- 공고를 **출처·지역 순**으로 정렬 (기업마당 → K스타트업 → 전국 → 서울 → 경기 → 인천 → 충청 → 기타)
- 각 공고마다 **제목·기관·마감·링크**를 평문으로 정리
- HTML 태그 제거, 길이 제한 (1,500자)

#### `claude_summarize()` (라인 4899) — AI 요약

- 15건 이내의 공고를 Claude에게 보내 **핵심만 3~5줄로 요약** 요청
- 실패하면 **기본 본문(fallback_body)**으로 대체
- Claude 없이도 동작 가능 (API 키 없으면 요약 건너뜀)

#### `mail_topic()` (라인 4743) — 메일 제목

- 소진공 정책자금 전용 제목 자동 선택
- 우선 키워드 빈도 top 2로 자동 라벨링 (예: "스마트팩토리·수출 공고")
- 키워드 없으면 "지원사업 공고"

#### 발송 함수들

| 함수 | 역할 |
|---|---|
| `send_email()` (5003) | SMTP로 실제로 메일 보내기 |
| `save_draft_to_gmail()` (5055) | Gmail 초안함에 IMAP으로 저장 |
| `draft_to_list()` (5086) | 여러 수신자에게 초안 일괄 생성 |
| `send_to_list()` (5109) | 여러 수신자에게 일괄 발송 |
| `deliver_with_outbox()` (5198) | **암호화된 대기열** 경유 발송 (중간에 꺼져도 재시도) |

### 🔴 안전 장치 (5중 방어)

```
① 기본값 "미리보기"    → --send 없으면 절대 안 보냄
② 중복 방지           → seen_ids.json에 기록, 다시 안 보냄
③ 발송 대기열         → 발송 전 암호화 저장, 실패 시 재시도
④ 경고 메일           → 수집 실패 시 관리자에게 자동 경고
⑤ 커버리지 점검       → 사이트 급감/정지 감지 → 폰 알림
```

#### 발송 대기열 (outbox) 상세

```
① deliver_with_outbox() → 수신자별로 암호화된 대기열에 먼저 저장
② send_to_list()       → 각 수신자에게 실제로 발송
③ delivery_outbox.settle() → 발송 성공/실패 기록
④ retry_pending_outbox() → 실패한 것만 다음 실행에서 재시도
⑤ persist_completed_outbox() → 완료된 것만 seen_ids에 반영
```

이렇게 하면 **중간에 프로그램이 꺼져도** 메일이 이중으로 안 가고, 빠진 것만 나중에 보충됩니다.

## 이 파일을 고칠 때 주의할 것

- **70곳**이 `from monitor import ...`로 이 파일의 함수를 가져다 씁니다 (테스트·스크립트)
- `execute_monitor()`는 `sites.json`·`groups.json`·`settings.json`을 읽어 동작합니다
- **실제 메일 발송은 절대 자동으로 안 됩니다** — 사람 승인이 필요합니다
- `ANTHROPIC_API_KEY`가 없으면 AI 요약이 빠지고, `BIZINFO_API_KEY`가 없으면 기업마당 수집이 안 됩니다
- `_ALLOW_SMTP_SEND` 플래그로 발송을 완전히 차단할 수 있습니다
