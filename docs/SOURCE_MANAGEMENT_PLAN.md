# 공고 수집 사이트 관리 계획

## 1. 현재 상태

- 활성 소스: 225개
- 비활성 소스: 189개
- 핵심 소스 2개: **기업마당(bizinfo)**, **K-Startup(kstartup)**

## 2. 수집 소스 계층 구조

```
┌─────────────────────────────────────────────────────────┐
│  Tier 1 (핵심) — 실패 시 즉시 알림 + 문제해결 필요          │
│                                                         │
│  ● 기업마당 (bizinfo)     — API 방식, 500건×20페이지       │
│  ● K-Startup (kstartup)  — HTML 파싱, 공공/민간 분리       │
└──────────────────────────┬──────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  Tier 2 (보조) — 실패 시 단순 로그 기록, 수집은 계속        │
│                                                         │
│  ● NIPA, KIAT, KEIT, KOSME, SBA 등 정부출연기관           │
│  ● 각 지역 테크노파크, 경제진흥원, 창조경제혁신센터           │
│  ● KOTRA, KITA 등 무역/수출 관련                          │
│  ● 기타 200+ 소스                                        │
└──────────────────────────┬──────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  Tier 3 (비활성) — 현재 수집 안 함, 향후 활성화 가능        │
│                                                         │
│  ● JS렌더링 필요 사이트 (SPA, 동적 페이지)                  │
│  ● 중복 소스 (KOTRA 등)                                   │
│  ● 접근 차단/구조 변경 사이트                               │
└─────────────────────────────────────────────────────────┘
```

## 3. 실패 처리 정책

| 구분 | Tier 1 (핵심) | Tier 2 (보조) |
|------|--------------|--------------|
| 실패 시 | 즉시 알림 (메일/ntfy) | 로그 기록만 |
| 연속 실패 시 | 문제 해결 시작 | 3회 연속 시 경고 |
| 복구 시 | 알림 해제 | 기록 없음 |
| 모니터링 | 매 수집마다 확인 | 에러만 기록 |

## 4. 구현 방안

### 4-1. sites.json에 tier 필드 추가

```json
{
  "id": "bizinfo",
  "name": "기업마당(Bizinfo)",
  "tier": 1,          // ← 신규: 1=핵심, 2=보조
  "enabled": true,
  ...
}
```

### 4-2. 수집 결과 추적

```json
// var/state/source_health.json (신규)
{
  "bizinfo": {
    "last_success": "2026-08-07T09:00:00",
    "last_failure": null,
    "consecutive_failures": 0,
    "status": "ok"
  },
  "kstartup": {
    "last_success": "2026-08-07T09:00:00",
    "last_failure": null,
    "consecutive_failures": 0,
    "status": "ok"
  }
}
```

### 4-3. 알림 로직

```
수집 실행
  ├─ Tier 1 실패 → source_health 업데이트 → 즉시 알림 발송
  │                → "기업마당 수집 실패! 확인 필요"
  ├─ Tier 2 실패 → source_health 업데이트 → 로그만
  │                → 3회 연속 시 경고 알림
  └─ 성공 → source_health 업데이트 → 알림 없음
```

### 4-4. 알림 채널

| 상황 | 채널 | 내용 |
|------|------|------|
| Tier 1 즉시 실패 | 메일 + ntfy | "⚠️ [소스명] 수집 실패 — 즉시 확인 필요" |
| Tier 1 복구 | ntfy | "✅ [소스명] 수집 정상 복구" |
| Tier 2 3회 연속 실패 | 메일만 | "⚠️ [소스명] 3회 연속 실패 — 점검 권장" |

## 5. 중복 제거 개선 계획

### 5-1. 현재 방식의 한계

```
현재: seen_ids(사이트별 ID) + 제목 정규화 비교

문제: 동일 공고가 다른 사이트에 게시되면 ID가 달라 중복으로 잡히지 않음

예시:
  A사이트 공고번호: A-2026-001
  B사이트 공고번호: B-88721
  → 내용은 동일 but ID 다르면 통과
```

### 5-2. 개선: 다단계 중복 판정

```
┌─────────────────────────────────────────────────────────┐
│  1순위: 원문 공고번호 비교                                  │
│  주관기관 공식 공고번호가 같으면 동일 공고                    │
│  예: "중소벤처기업부 공고 제2026-123호"                     │
└──────────────────────────┬──────────────────────────────┘
                           │ 불일치
                           ▼
┌─────────────────────────────────────────────────────────┐
│  2순위: 원문 URL 비교                                      │
│  동일 원문 페이지 또는 동일 첨부파일 링크 → 동일 공고         │
└──────────────────────────┬──────────────────────────────┘
                           │ 불일치
                           ▼
┌─────────────────────────────────────────────────────────┐
│  3순위: 첨부파일 해시 비교                                  │
│  PDF/HWP 파일 내용이 같으면 동일 공고 (파일명 무관)          │
└──────────────────────────┬──────────────────────────────┘
                           │ 불일치
                           ▼
┌─────────────────────────────────────────────────────────┐
│  4순위: 정규화된 제목 비교                                  │
│  [공고][재공고][서울]2026년/모집기간/기관명/특수문자/공백 제거 │
│  핵심 제목 같으면 중복                                      │
└──────────────────────────┬──────────────────────────────┘
                           │ 불일치
                           ▼
┌─────────────────────────────────────────────────────────┐
│  5순위: 핵심 내용 비교 (유사도)                              │
│  사업명(30%) + 주관기관(20%) + 신청대상(15%)                │
│  + 지원금액(10%) + 접수기간(10%) + 지역(5%)                 │
│  + 첨부파일명·내용(10%)                                     │
│  유사도 ≥ 임계값 → 동일 공고                                │
└──────────────────────────┬──────────────────────────────┘
                           │ 불일치
                           ▼
┌─────────────────────────────────────────────────────────┐
│  6순위: 게시일 차이 확인 (보조)                              │
│  동일 공고가 1~7일 차이로 게시될 수 있음                     │
│  게시일이 다르더라도 중복 가능                               │
└─────────────────────────────────────────────────────────┘
```

### 5-3. 중복 공고 대표본 선정

동일 공고가 여러 사이트에 있을 경우:

| 우선순위 | 출처 | 설명 |
|---------|------|------|
| 1 | 주관기관 사이트 | 공고를 직접 발행한 기관 |
| 2 | K-Startup | 공식 사업 신청 사이트 |
| 3 | 기업마당 | 정부 통합공고 사이트 |
| 4 | 지역기관 | 재게시 공고 |
| 5 | 민간 | 재가공 사이트 |

대표 공고에 다른 출처도 함께 표시:
```
공식 원문: K-Startup
추가 출처: 기업마당, 서울경제진흥원
```

### 5-4. 구현 범위

| 단계 | 내용 | 우선순위 |
|------|------|---------|
| Phase 1 | 제목 정규화 강화 (4순위) | 즉시 |
| Phase 2 | 원문 URL 비교 (2순위) | 다음 |
| Phase 3 | 첨부파일 해시 비교 (3순위) | 추후 |
| Phase 4 | 핵심 내용 유사도 비교 (5순위) | 추후 |

## 6. 지원내용 확인

### 6-1. 포함할 지원유형

예비창업 공고에서 다음 유형을 우선 포함합니다.

| 지원유형 | 예시 |
|---------|------|
| 사업화자금 | 사업화비, 창업지원금 |
| 시제품 제작 | 제품개발비, 시제품 제작비 |
| R&D | 기술개발비, 연구개발비 |
| 바우처 | 제조, 디자인, 마케팅, 수출 바우처 |
| 입주공간 + 사업비 | 공간 + 사업화자금 결합 |
| 판로·실증 | PoC, 테스트베드, 실증비 |
| 지식재산 | 특허·상표 출원비 |
| 마케팅 | 광고비, 콘텐츠 제작비 |
| 해외진출 | 전시회 참가비, 수출지원금 |

### 6-2. 원칙적으로 제외할 지원유형

다음 지원만 **단독으로** 제공하는 경우 제외합니다.

- 교육
- 멘토링
- 코칭
- 상담
- 컨설팅
- 역량강화
- 세미나
- 워크숍
- 설명회
- 네트워킹

### 6-3. 투자 공고 제외

다음 투자 관련 공고는 제외합니다.

- 엔젤투자
- VC 투자
- 시드투자
- 지분투자
- 투자기관 매칭

> **예외:** 사업화자금 지원공고의 부가 프로그램으로 IR 교육이 포함된 경우에는 제외하지 않습니다.

## 8. 제외 키워드 적용 방식 수정

### 6-1. 현재 방식의 문제

```
현재: 본문에 "멘토링","컨설팅","교육" 있으면 → 무조건 제외

문제: 사업화자금 + 멘토링 같은 정상 공고도 떨어짐

예시:
  "AI 사업화자금 최대 5,000만 원과 전문가 멘토링 지원"
  → 본문에 "멘토링" 있음 → 제외됨 (잘못됨)
```

### 6-2. 수정 원칙: 본문 전체가 아니라 우선순위로 판단

```
┌─────────────────────────────────────────────────────────┐
│  1순위: 제목과 사업 목적 확인                               │
│                                                         │
│  제목                          판단                       │
│  ─────────────────────────────────────────────          │
│  예비창업자 AI 사업화 지원사업 모집  → 포함                 │
│  예비창업자 멘토링 프로그램 모집     → 제외                 │
│  창업교육 수강생 모집               → 제외                 │
│  사업화자금 및 멘토링 지원          → 포함                 │
└──────────────────────────┬──────────────────────────────┘
                           │ 불명확
                           ▼
┌─────────────────────────────────────────────────────────┐
│  2순위: 주된 지원내용 확인                                 │
│                                                         │
│  지원 구성                      판단                       │
│  ─────────────────────────────────────────────          │
│  사업화자금 + 멘토링              → 포함 (자금이 핵심)       │
│  시제품 제작비 + 교육             → 포함 (제작비가 핵심)     │
│  바우처 + 컨설팅                  → 포함 (바우처가 핵심)     │
│  교육만 제공                     → 제외                    │
│  멘토링만 제공                   → 제외                    │
│  상담만 제공                     → 제외                    │
└──────────────────────────┬──────────────────────────────┘
                           │ 불명확
                           ▼
┌─────────────────────────────────────────────────────────┐
│  3순위: 부가 지원 여부 확인                                │
│                                                         │
│  포함 (부가 프로그램)             제외 (단독 프로그램)      │
│  ─────────────────────          ─────────────────────   │
│  사업화자금 + 멘토링              무료 창업교육              │
│  시제품비 + 역량강화 교육          1:1 전문가 멘토링          │
│  PoC 비용 + 전문가 컨설팅          창업상담 프로그램          │
│  R&D 자금 + 기술사업화 코칭        네트워킹 및 세미나          │
│                                  투자유치 교육              │
└─────────────────────────────────────────────────────────┘
```

### 6-3. 구현 방식

| 단계 | 내용 | 설명 |
|------|------|------|
| 1 | 제목에서 제외 키워드 위치 확인 | 제목에 "멘토링/컨설팅/교육"이 핵심이면 제외 |
| 2 | 본문에서 지원 내용 우선순위 추출 | 자금/바우처/R&D가 있으면 포함 |
| 3 | 제외 키워드가 부가 프로그램인지 판정 | 핵심 지원 + 부가 멘토링 → 포함 |

## 7. 예비창업 지원대상 판정

### 8-1. 키워드 전체 검색의 문제

```
현재: 본문 아무 곳에 "예비창업자" 있으면 → 포함

문제: 지원기관 모집 공고도 "예비창업자"가 본문에 있음

예시:
  "예비창업자를 지원할 창업보육 전문기관 모집"
  → 예비창업자가 신청하는 공고가 아님 (잘못됨)
```

### 8-2. 지원대상 구역 우선 추출

본문에서 다음 제목의 문단을 찾아 지원대상 추출:

```
검색 대상 라벨:
  - 지원대상 / 신청대상 / 모집대상 / 참여대상
  - 신청자격 / 지원자격 / 신청요건 / 자격요건
  - 신청 가능 대상 / 누가 신청할 수 있나요 / 대상자
```

### 8-3. 지원대상 추출 우선순위

```
┌─────────────────────────────────────────────────────────┐
│  1순위: 구조화된 지원대상 필드                              │
│  K-Startup "대상", 기업마당 "지원대상" 등                  │
│  → target_field에 이미 추출됨                             │
└──────────────────────────┬──────────────────────────────┘
                           │ 없음
                           ▼
┌─────────────────────────────────────────────────────────┐
│  2순위: 본문의 지원대상 문단                               │
│  "지원대상" 라벨 아래 문장 추출                            │
└──────────────────────────┬──────────────────────────────┘
                           │ 없음
                           ▼
┌─────────────────────────────────────────────────────────┐
│  3순위: 첨부 공고문                                       │
│  웹페이지에 없으면 첨부 PDF/HWP의 신청자격 문단 확인         │
└──────────────────────────┬──────────────────────────────┘
                           │ 없음
                           ▼
┌─────────────────────────────────────────────────────────┐
│  4순위: 제목 및 요약 (보조)                                │
│  지원대상 문단 못 찾은 경우에만 제목/요약 사용              │
└──────────────────────────┬──────────────────────────────┘
                           │ 불명확
                           ▼
┌─────────────────────────────────────────────────────────┐
│  5순위: AI 판정                                          │
│  지원대상 불명확 또는 충돌 시 AI가 판단                     │
└─────────────────────────────────────────────────────────┘
```

### 8-4. 예비창업 인정 표현

| 표현 | 판단 |
|------|------|
| 예비창업자 | 인정 |

| 개인 또는 팀 단위의 창업 준비자 | 인정 |
| 신규 창업을 준비 중인 자 | 인정 |
| 공고일 기준 사업자 미보유자 | 인정 |
| 사업자등록 전 개인 | 인정 |

### 8-2. 권장 판정 기준

예비창업 여부는 다음 순서로 판단합니다.

**1순위: 사업자등록 보유 여부**

| 조건 | 판단 |
|------|------|
| 사업자등록 없음 | 예비창업 가능 |
| 법인등기 없음 | 예비창업 가능 |
| 사업자등록 보유 필수 | 예비창업 제외 |

**2순위: 지원대상 표현**

- 예비창업자
- 창업예정자
- 사업자 미등록자
- 신규창업 준비자
- 개인 또는 팀
- 공고일 현재 사업자등록이 없는 자

**3순위: 창업기준일**

다음 조건이 있는지 확인합니다.

- 공고일 현재 사업자 미보유
- 신청일 현재 사업자 미보유
- 협약일까지 사업자등록 필요
- 선정 후 사업자등록 가능
- 과거 폐업 이력 제한
- 동일 업종 재창업 제한

**4순위: 기존 사업자 포함 여부**

예비창업자와 기존 기업이 함께 지원 가능한 공고도 포함할 수 있습니다.

예시: "예비창업자 및 창업 3년 이내 기업"

메일 표시: "예비창업자 신청 가능 / 창업기업도 함께 모집"

## 9. 공고 적합도 점수

적합도 점수는 현재 단계에서 **필수 판단기준으로 사용하지 않고 참고정보로만 유지**하는 것이 적절합니다.

**권장 용도**
- 메일 내 공고 정렬
- 우선 검토 공고 선정
- AI 판정 대상 우선순위 설정
- 운영자가 오탐·누락을 검토할 때 참고

**사용하지 않는 것이 좋은 용도**
- 점수가 낮다는 이유만으로 자동 제외
- 점수가 높다는 이유만으로 자동 승인
- 지원대상 확인 없이 키워드 점수만으로 확정

지원대상, 지원내용, 지역, 마감 여부가 확인된 후 참고 점수를 계산하는 방식이 적절합니다.

## 10. AI 판정 범위

### 10-1. 모든 수집 공고를 AI가 판단하는 방식

행정성 필터와 중복 제거만 마친 모든 공고를 AI에 보내는 것도 기술적으로는 가능합니다.

다만 다음 문제가 발생할 수 있습니다.

- 처리 건수 증가
- 토큰 사용량 증가
- 처리시간 증가
- 동일한 단순 공고까지 반복 판정
- AI의 판단 변동 가능성
- 오류 발생 시 전체 파이프라인 지연

### 10-2. 가정 시나리오

하루 수집 공고를 1,000건으로 가정하면 다음과 같습니다.

| 단계 | 예상 잔여 공고 |
|------|---------------|
| 전체 수집 | 1,000건 |
| 행정성 공고 제외 | 600건 |
| 중복 제거 | 450건 |
| 지원대상 문단 추출 | 150건 |
| 지원내용·지역·마감 필터 | 30~70건 |
| AI 최종 판정 | 30~70건 |

전체 450건을 AI가 판정하는 것보다 규칙 기반으로 후보를 30~70건까지 줄인 뒤 AI를 사용하는 것이 효율적입니다.

### 10-3. 권장 AI 사용 방식

**AI가 반드시 판단할 공고**

- 지원대상 문장이 불명확한 공고
- 예비창업자와 기존 기업 조건이 혼합된 공고
- 지역 조건이 여러 문단에서 충돌하는 공고
- 사업화자금과 교육 프로그램이 혼합된 공고
- 제목과 본문의 신청대상이 다른 공고
- 수행기관 모집인지 참여자 모집인지 불명확한 공고
- 공고문 첨부파일에만 신청자격이 있는 공고

**규칙만으로 확정 가능한 공고 (자동 포함)**

- 지원대상에 '공고일 현재 사업자등록이 없는 예비창업자'라고 명확히 기재
- 사업화자금 지원 금액이 명시
- 전국 대상
- 접수 중
- 참여자 모집공고임이 명확

이런 공고는 AI를 거치지 않고 자동 포함해도 됩니다.

**규칙만으로 제외 가능한 공고 (자동 제외)**

- 결과 발표
- 입찰공고
- 평가위원 모집
- 지원기관 모집
- 단순 설명회
- 접수 마감
- 특정 타지역 주민만 신청 가능
- 사업자등록 보유기업만 신청 가능

이런 공고는 AI를 거치지 않고 즉시 제외합니다.

① 공고 수집
