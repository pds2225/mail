# 예비창업 지원사업 공고 추천 시스템 — 최종 실행계획서

---

## 1. 계획 개요

### 추진 배경

현재 mail 모니터 시스템은 225개 소스에서 공고를 수집하고 있으나, 다음과 같은 문제가 있습니다.

- 본문에 "멘토링"이 포함됐다는 이유로 사업화자금 공고가 제외됨
- 동일 공고가 여러 사이트에 게시되면 중복으로 처리되지 않음
- 수정공고·마감연장이 일반 중복으로 삭제됨
- 소스 장애 시 품질 저하를 감지하지 못함

### 최종 목적

> 전국 또는 서울·경기·인천의 예비창업자, 사업자 미보유 창업예정자가 실제 신청할 수 있고 현재 접수 중이며, 사업화자금·시제품 제작비·R&D·바우처·실증비 등 실질적인 비용지원이 포함된 공고를 최대한 누락 없이 수집한다.
> 교육·멘토링·컨설팅·투자·입주공간만 제공하는 공고, 운영기관 모집, 행정성 공고, 마감공고는 제외한다.
> 여러 사이트에 게시된 동일 공고는 하나의 통합 공고로 관리하되, 수정공고·재공고·마감연장 등 중요 변경사항은 별도 버전으로 관리하고 필요 시 다시 안내한다.

### 적용 범위

- 대상 그룹: `grp_prestartup_ai` (예비창업 AI)
- 수집 소스: 활성 225개 (Tier 1: 2개, Tier 2: 223개)
- 발송 대상: 서울·경기·인천 거주 예비창업자

### 핵심 성공기준

| 기준 | 목표 |
|------|------|
| 예비창업 공고 정밀도 | 95% 이상 |
| 예비창업 공고 재현율 | 90% 이상 |
| 사이트 간 중복 제거율 | 90% 이상 |
| 사업비+멘토링 공고 오제외 | 0건 |
| Tier 1 수집 성공률 | 99% 이상 |

## 2. 현재 상태 진단

### 활성·비활성 소스 현황

| 구분 | 수량 | 비고 |
|------|------|------|

### 핵심 수집처

| Tier | 소스 ID | 소스명 | 수집 방식 |
|------|---------|--------|----------|
| 1 | `bizinfo` | 기업마당 | API (500건×20페이지) |
| 1 | `kstartup` | K-Startup | HTML 파싱 (공공/민간 분리) |
| 2 | `nipa` | NIPA | HTML 파싱 |
| 2 | `kiat` | KIAT | HTML 파싱 |
| 2 | `sba` | 서울산업진흥원 | HTML 파싱 |

### 현재 구조의 문제점

| 문제 | 설명 |
|------|------|
| 수집·중복·매칭 혼재 | 한 파일에서 모든 처리를 담당하여 변경 영향 추적 어려움 |
| 성공 판정 부족 | HTTP 200이어도 파싱 0건이면 장애를 놓침 |

| 제목 정규화 과도 | 연도·지역·차수를 삭제하여 다른 공고를 동일 공고로 오인 |
| 키워드 단독 제외 | 본문에 "멘토링"이 있으면 사업화자금 공고도 제외 |

## 4. 수집 소스 관리 계획 (모듈 A)

### 4-1. Tier 구조

| Tier | 기준 | 소스 | 실패 시 |
|------|------|------|--------|
| 1 (핵심) | 공고의 원천이 되는 통합 포털 | bizinfo, kstartup | 즉시 알림 + 문제해결 |
| 2 (보조) | 정부출연기관, 지역 TP 등 | nipa, kiat, sba 등 223개 | 로그 기록, 임계값 도달 시 경고 |
| 3 (비활성) | JS렌더링 필요, 접근차단, 중복 | 189개 | 수집 안 함 |

**Tier는 기관명이 아니라 수집기 단위(source_id)로 관리합니다.**

```json
{
  "id": "kotra_main",
  "name": "KOTRA 사업공고",
  "tier": 2,
  "enabled": true
}
```

```json
{
  "id": "kotra_duplicate_board",
  "name": "KOTRA 재게시 게시판",
  "tier": 3,
  "enabled": false,
  "disabled_reason": "핵심 게시판과 중복"
}
```

### 4-2. 소스 상태값

| 상태 | 의미 | 조건 |
|------|------|------|
| `OK` | 정상 수집 및 파싱 완료 | 모든 검증 통과 |
| `DEGRADED` | 일부 실패 | 일부 페이지/필드 실패, 건수 급감 |
| `FAILING` | 수집 실행 실패 | HTTP 오류, 파싱 예외 |
| `STALE` | 신선도 이상 | 마지막 성공 후 허용시간 초과 |
| `DISABLED` | 운영자 비활성화 | 수동 설정 |
| `UNKNOWN` | 초기 상태 | 아직 수집 안 됨 |

### 4-3. 데이터 품질 검증

수집 성공은 다음 조건을 모두 충족해야 합니다.

```
HTTP/API 응답 성공
AND 예상 페이지 수 처리 완료
AND 필수 필드 파싱률 ≥ 80%
AND 수집 건수 급격한 감소 없음 (평소의 50% 이상)
AND 최신 공고 날짜가 허용 범위 내 (7일 이내)
AND 제목·URL 빈값 비율 ≤ 20%
```

**부분 실패(DEGRADED) 조건:**
- 일부 페이지만 수집 (K-Startup 공공만 성공, 민간 실패)
- 필수 필드 파싱률 50~80%
- 수집 건수가 평소의 50% 미만

### 4-4. 소스별 설정

```json
{
  "expected_interval_minutes": 360,
  "failure_threshold": 3,
  "max_staleness_minutes": 1440,
  "alert_cooldown_minutes": 360,
  "min_expected_count": 10,
  "page_count_expected": 5
}
```

### 4-5. Tier별 실패 정책

**Tier 1:**
- 최초 실패 즉시 알림 (메일 + ntfy)
- 연속 실패 추적
- 쿨다운 경과 후 재알림
- 정상 복구 시 1회 복구 알림

**Tier 2:**
- 기본적으로 로그 기록만
- 연속 실패 임계값 도달 시 경고
- 마지막 성공 후 허용시간 초과 시에도 경고

### 4-6. 알림 폭주 방지

| 상태 전환 | 알림 |
|-----------|------|
| OK → FAILING | 신규 장애 알림 1회 |
| FAILING → FAILING | 쿨다운 이전 재알림 금지 |
| 장기 장애 | 쿨다운 경과 후 재알림 |
| FAILING → OK | 복구 알림 1회 |
| 복구 후 재실패 | 새로운 장애로 처리 |

### 4-7. 알림 내용

```
소스명: 기업마당
소스 ID: bizinfo
Tier: 1
상태: FAILING
실패 시각: 2026-08-07 09:00:00
마지막 성공: 2026-08-07 03:00:00
연속 실패: 2회
수집 건수: 0건 (평소: 450건)
오류 유형: HTTP_TIMEOUT
오류 메시지: Connection timeout after 30s
실행 ID: run-20260807-090000
```

### 4-8. 상태 저장 구조

```
source_registry          — 소스 설정 (Tier, 주기, 임계값)
source_run_history       — 실행별 이력 (성공/실패, 건수, 소요시간)
source_current_health    — 현재 상태 (상태값, 마지막 성공/실패)
source_incident_history  — 장애·복구 이력 (알림 발송 여부)
```

동시 실행 안전성: 임시파일 작성 후 원자적 교체 방식 적용.

## 5. 공고 통합·중복 제거 계획 (모듈 B)

### 5-1. 데이터 구조 분리

| 항목 | 의미 | 용도 |
|------|------|------|
| `source_notice_id` | 사이트별 원본 공고 ID | 사이트 내부 중복 제거 |
| `canonical_notice_id` | 여러 사이트의 동일 사업 통합 ID | 사이트 간 중복 제거 |
| `delivery_history` | 특정 그룹 발송 이력 | 중복 발송 차단 |

기존 `seen_ids`는 동일 사이트의 재수집 방지 용도로만 사용합니다.

### 5-2. 중복 판정 우선순위

```
1순위: 공식 공고번호 비교
       → "중소벤처기업부 공고 제2026-123호" 같으면 동일

2순위: 정규화된 공식 원문 URL 비교
       → 동일 원문 페이지면 동일

3순위: 공식 신청 URL 비교
       → 동일 신청 페이지면 동일

4순위: 안전한 제목 + 기관 + 연도 + 차수 + 접수기간 결합 비교
       → 모든 항목이 일치하면 동일

5순위: 첨부파일 내용 해시
       → PDF/HWP 내용이 같으면 동일

6순위: 핵심 필드 유사도 비교
       → 사업명(30%) + 주관기관(20%) + 신청대상(15%) + 금액(10%)

7순위: 게시일 차이는 보조자료로만 사용
       → 게시일이 다르더라도 동일 공고 가능
```

### 5-3. 제목 정규화 규칙

**보존해야 하는 정보 (삭제 금지):**
- 사업연도 (2025년 ≠ 2026년)
- 모집 차수 (1차 ≠ 2차)
- 지역 (서울 ≠ 부산)
- 주관기관
- 재공고·추가공고·수정공고 여부
- 접수기간
- 사업명 핸심 고유어

**정규화 대상 (표현 차이만 통일):**
- 중복 공백 제거
- 특수문자 통일
- `모집 공고` → `모집공고`
- `예비 창업자` → `예비창업자`
- 괄호·구분기호 통일
- URL 추적 파라미터 제거

### 5-4. 수정·재공고·마감연장 버전 관리

```
canonical_notice (공고 계열)
 ├─ version 1: 최초 공고 (2026-08-01)
 ├─ version 2: 수정공고 (2026-08-05) — 지원대상 변경
 └─ version 3: 마감연장 (2026-08-10) — 접수기간 연장
```

**버전별 저장 정보:**
- 변경일시
- 변경 유형 (CREATED, MODIFIED, EXTENDED, CORRECTED)
- 변경된 필드
- 변경 전/후 값
- 중요도 (HIGH, MEDIUM, LOW)
- 재발송 필요 여부
- 원문 출처

### 5-5. 변경공고 재발송 정책

| 변경사항 | 중요도 | 재발송 |
|----------|--------|--------|
| 접수기간 연장 | HIGH | 재발송 |
| 지원대상 변경 | HIGH | 재발송 |
| 지원금액 변경 | HIGH | 재발송 |
| 제출서류 변경 | MEDIUM | 중요도에 따라 |
| 신청링크 변경 | HIGH | 재발송 |
| 단순 오탈자 | LOW | 재발송 안 함 |
| 동일 공고 타사이트 재게시 | - | 재발송 안 함 |

### 5-6. 필드 병합 (대표본 선택이 아닌)

동일 공고의 여러 출처 중 가장 신뢰도 높은 정보를 병합합니다.

```
대표 제목: 주관기관 공식 제목
공식 공고문: 주관기관 URL
신청 링크: K-Startup URL (실제 신청 가능)
지원대상: 가장 구조화되고 최신인 값
접수기간: 최신 수정공고 기준
지원금액: 가장 구체적인 값
추가 출처: 기업마당, 지역기관
```

**대표 출처 우선순위:**
1. 직접 발행한 주관기관 공식 사이트
2. 실제 신청이 진행되는 공식 접수 사이트
3. K-Startup
4. 기업마당
5. 지역기관 재게시
6. 기타 민간·재가공 사이트

단, 최신 수정정보가 하위 출처에만 있는 경우 최신성을 우선합니다.

## 6. 예비창업 공고 판정 계획 (모듈 C)

### 6-1. 행정성 공고 제외

**판정 우선순위:**
1. 공고의 주된 목적
2. 제목
3. 실제 신청자
4. 주된 지원내용
5. 본문 키워드 보조판정

**자동 제외 대상:**
- 입찰, 용역, 구매계약
- 심사위원·평가위원·운영위원 모집
- 직원 채용, 재직자 모집
- 결과 발표, 선정 결과, 보도자료
- 행정고지
- 운영기관 모집, 수행기관 모집, 주관기관 모집
- 단순 설명회, 단순 행사 안내

### 6-2. 지원대상 추출

**추출 우선순위:**
1. 구조화된 `target_field` (K-Startup "대상", 기업마당 "지원대상")
2. 본문의 지원대상·신청자격 문단
3. 첨부 공고문
4. 제목·본문 요약 (보조)
5. AI 판정

**검색 라벨:**
- 지원대상, 신청대상, 모집대상, 참여대상
- 신청자격, 지원자격, 신청요건, 자격요건
- 신청 가능 대상, 대상자, 누가 신청할 수 있나요

### 6-3. 신청자와 수혜자 구분

| 역할 | 설명 | 예시 |
|------|------|------|
| 신청자 | 실제 신청서를 제출하는 주체 | 예비창업자 |
| 모집대상 | 공고가 직접 모집하는 대상 | 예비창업자 |
| 수혜자 | 최종 지원을 받는 대상 | 예비창업자 |
| 운영자 | 프로그램을 운영하는 기관 | 대학, 창업지원기관 |

**최종 매칭은 신청자와 모집대상을 기준으로 합니다.**

**제외 예시:**
```
"예비창업자를 지원할 창업보육 전문기관 모집"
→ 본문에 예비창업자 있지만 신청자가 기관이므로 제외
```

### 6-4. 예비창업 인정 기준

**인정 표현:**
- 예비창업자
- 창업예정자
- 신규창업 준비자
- 사업자등록을 하지 않은 자
- 신청일 현재 사업자등록이 없는 자
- 공고일 현재 사업자 미보유자
- 선정 후 사업자등록 예정자
- 협약 전 사업자등록 예정자
- 법인설립 전 대표자

**`개인` 단독 인정 금지:**
```
"개인"만으로는 예비창업자로 인정하지 않음

인정 조건:
  "개인 또는 팀"
  AND
  "창업예정" 또는 "사업자 미등록" 또는 "신규 창업 준비"
```

**판정 상태:**

| 상태 | 의미 |
|------|------|
| `ELIGIBLE` | 명확하게 예비창업 신청 가능 |
| `INELIGIBLE` | 명확하게 불가 |
| `CONDITIONAL` | 폐업·업종·대표이력 등 추가 조건 |
| `UNKNOWN` | 확인 불가 |

**조건부 판정 대상:**
- 기존 사업자 보유 여부
- 동일 업종 사업자 여부
- 폐업 이력 및 경과기간
- 법인 대표이력
- 선정 전/협약 전 폐업 조건

### 6-5. 지원내용 판정

**포함할 실질 지원 (비용지원):**

| 유형 | 예시 |
|------|------|
| 사업화자금 | 사업화비, 창업지원금 |
| 시제품 제작 | 제품개발비, 시제품 제작비 |
| R&D | 기술개발비, 연구개발비 |
| 바우처 | 제조, 디자인, 마케팅, 수출 바우처 |
| 실증·PoC | 테스트베드 비용, 실증비 |
| 지식재산 | 특허·상표 출원비 |
| 마케팅 | 광고비, 콘텐츠 제작비 |
| 해외진출 | 전시회 참가비, 수출지원금 |
| 입주+사업비 | 공간 + 사업화자금 결합 |

**단독 제공 시 제외:**

| 구분 | 제외 대상 |
|------|----------|
| 교육·상담 | 교육, 멘토링, 코칭, 상담, 컨설팅, 역량강화 |
| 행사 | 세미나, 워크숍, 설명회, 네트워킹, 커뮤니티 |
| 투자 | 엔젤투자, VC, 시드투자, 지분투자, 데모데이, IR 피칭 |
| 공간 | 입주공간만 제공 |

**부가 프로그램 예외 (포함):**
- 사업화자금 + 멘토링 → 포함 (자금이 핵심)
- 시제품 제작비 + 교육 → 포함 (제작비가 핵심)
- 바우처 + 컨설팅 → 포함 (바우처가 핵심)
- R&D 자금 + 코칭 → 포함 (R&D가 핵심)
- 입주공간 + 사업화자금 → 포함 (사업비가 핵심)

**입주기업 키워드 처리:**

| 구성 | 판단 |
|------|------|
| 입주공간만 제공 | 제외 |
| 입주공간 + 사업화자금 | 포함 |
| 입주공간 + 시제품 제작비 | 포함 |
| 입주공간 + 실증비 | 포함 |
| 입주공간 + 교육만 제공 | 제외 |
| 입주공간 + 투자연계만 제공 | 제외 |

**지원금 수령 주체 확인:**

본문에 지원금이 있다고 해서 모두 포함하지 않습니다. 다음은 제외 대상:
- 운영기관 사업비
- 수행기관 위탁비
- 투자금 유치 교육
- 대출·융자 안내
- 참가비 납부
- 전체 사업예산 설명

**핵심 확인:** 예비창업자인 신청자가 직접 또는 서비스 형태로 실질적인 비용지원을 받는가

**`support_types` 변경:**

| 구분 | 지원유형 |
|------|---------|
| 자동 포함 | 지원금, 바우처, R&D, 시제품 제작, 실증·PoC, 사업비 결합 입주, 비용지원형 마케팅·판로·해외진출 |
| 자동 제외 | 교육 단독, 멘토링 단독, 컨설팅 단독, 투자 단독, 입주공간 단독 |
| AI/사람 검토 | 복합지원, 지원금액 불명확, 그외, 비용지원 수령 주체 불명확 |

### 6-6. 지역 판정

**신청자의 자격조건을 기준으로 판단 (게시기관 소재지가 아님)**

**우선순위:**
1. 신청대상 문단의 지역조건
2. 거주지 조건
3. 사업예정지 조건
4. 선정 후 이전·입주·사업자등록 조건
5. 구조화된 지역 필드
6. 게시기관 소재지 (최후 보조)

**판정:**

| 조건 | 처리 |
|------|------|
| 전국 대상 | 포함 |
| 지역 제한 없음 | 포함 |
| 서울·경기·인천 대상 | 포함 |
| 서울·경기·인천에서 창업 예정 | 포함 |
| 특정 타지역 거주자만 가능 | 제외 |
| 특정 타지역 창업예정자만 가능 | 제외 |
| 전국 신청 가능, 선정 후 타지역 이전 필수 | 조건부 포함 |

**예시:**
```
대구 소재 기관이 전국 예비창업자를 모집 → 포함
선정 후 대구 이전 조건 → "전국 신청 가능 / 선정 후 대구 사업자등록 필수"
```

### 6-7. 마감 판정

**상태:**

| 상태 | 의미 |
|------|------|
| `OPEN` | 접수 중 |
| `CLOSED` | 마감 |
| `ALWAYS_OPEN` | 상시접수 |
| `UNTIL_BUDGET_EXHAUSTED` | 예산 소진 시까지 |
| `EXTENDED` | 마감연장 |
| `UNKNOWN` | 확인 불가 |

**판정 규칙:**
- 마감일 경과 시 `CLOSED`
- 연장공고가 있으면 최신 마감일 적용
- 신청 페이지가 닫혔으면 `CLOSED`
- 예산 소진 시까지는 `OPEN`
- 접수기간이 여러 출처에서 다르면 최신 공식 공고 우선
- 한국 공고는 `Asia/Seoul` 기준

## 7. AI 판정 계획

### 7-1. 호출 조건

기본 모드: `ambiguous_only`

### 7-2. AI 호출 대상 사유코드

| 사유코드 | 설명 |
|----------|------|

| `PRIMARY_SUPPORT_MIXED` | 주된 지원과 부가 지원 혼합 |
| `REGION_CONFLICT` | 지역 조건 충돌 |
| `POST_SELECTION_RELOCATION` | 선정 후 이전 조건 |
| `DEADLINE_CONFLICT` | 접수기간 충돌 |
| `OPERATOR_OR_PARTICIPANT_UNCLEAR` | 운영기관 모집인지 참여자 모집인지 불명확 |
| `POSSIBLE_DUPLICATE` | 중복 가능성 |
| `BUSINESS_HISTORY_CONDITION` | 폐업·업종 이력 조건 |
| `MULTIPLE_ELIGIBILITY_RULES` | 복수 자격 요건 |

### 7-3. AI 운영 통제

- 하루 최대 호출 건수: `llm_call_limit_per_run` (기본 30)
- 동일 공고 결과 캐시
- 공고 내용 변경 시 캐시 무효화
- JSON 스키마 검증
- 사용 모델명·버전 저장
- 타임아웃: 30초
- 재시도: 2회
- AI 실패 시 `HUMAN_REVIEW` 상태
- AI 실패 시 자동 포함·자동 제외 금지
- 판정 근거 원문 저장

### 7-4. AI 출력 스키마

```json
{
  "decision": "INCLUDE | EXCLUDE | CONDITIONAL | HUMAN_REVIEW",
```

## 11. 테스트 및 검증계획

### 11-1. 단위 테스트

**수집 소스:**
- Tier 1 정상수집 → `OK` 상태
- HTTP 성공이나 파싱 0건 → `DEGRADED` 상태
- 일부 페이지만 실패 → `DEGRADED` 상태
- 필수 필드 빈값 증가 → `DEGRADED` 상태
- 수집 건수 급감 → `DEGRADED` 상태
- 마지막 성공 이후 stale → `STALE` 상태
- 장애 알림 중복 방지 → 쿨다운 적용
- 복구 알림 → 1회만 발송

**중복 제거:**
- 동일 사이트 동일 ID → 중복 제거
- 다른 사이트 동일 공고번호 → 통합
- 8월 17일과 8월 18일 게시된 동일 공고 → 통합
- 제목 표현만 다른 동일 공고 → 통합
- 연도만 다른 별도 공고 → 별도 유지
- 지역만 다른 별도 공고 → 별도 유지
- 1차·2차 모집 → 별도 버전
- 수정공고 → 버전 추가
- 마감연장 → 버전 추가

**지원대상:**
- 명확한 예비창업자 → `ELIGIBLE`
- 개인 단독 표현 → `UNKNOWN` (추가 확인 필요)
- 개인 또는 팀 + 창업예정 → `ELIGIBLE`
- 예비창업자를 지원할 운영기관 모집 → `INELIGIBLE`
- 사업자등록 보유기업만 가능 → `INELIGIBLE`

**지원내용:**
- 사업화자금 + 멘토링 → 포함
- 교육 단독 → 제외
- 입주공간 단독 → 제외
- 입주공간 + 사업화자금 → 포함

**지역:**
- 전국 대상 → 포함
- 대구기관의 전국 대상 공고 → 포함
- 부산 거주자 한정 → 제외 (서울 그룹 기준)

### 11-2. 통합 테스트

- 전체 파이프라인 실행 (수집 → 중복 → 매칭 → 발송)
- Tier 1 장애 시 알림 발송
- 수정공고 감지 및 재발송
- AI 판정 캐시 동작

### 11-3. 정답 데이터셋

과거 실제 공고 100~200건을 사람이 라벨링:

```
INCLUDE        — 예비창업자가 신청 가능한 비용지원 공고
EXCLUDE        — 교육·멘토링·투자·운영기관 모집 등
CONDITIONAL    — 조건부 포함 (폐업자, 지역이전 등)
HUMAN_REVIEW   — 판정 불가, 사람 확인 필요
DUPLICATE      — 동일 공고의 다른 사이트 버전
IMPORTANT_UPDATE — 수정·연장된 중요 변경 공고
```

### 11-4. KPI

| KPI | 1차 목표 | 측정 방법 |
|-----|---------|----------|
| 예비창업 공고 정밀도 | 95% 이상 | 포함된 공고 중 실제 예비창업자 대상 비율 |
| 예비창업 공고 재현율 | 90% 이상 | 실제 예비창업자 공고 중 수집된 비율 |
| 사이트 간 중복 제거율 | 90% 이상 | 동일 공고 중 통합된 비율 |
| 잘못된 중복 제거율 | 1% 이하 | 다른 공고인데 통합된 비율 |
| 사업비+멘토링 오제외 | 0건 | 포함해야 할 공고가 제외된 건수 |
| 운영기관 모집 오포함 | 0건 | 제외해야 할 공고가 포함된 건수 |
| 개인 단독 오포함 | 0건 | 개인만으로 포함된 건수 |
| Tier 1 수집 성공률 | 99% 이상 | 성공 실행 / 전체 실행 |
| Tier 1 장애 감지시간 | 1회 실행주기 이내 | 장애 발생 ~ 알림 발송 |
| AI 전달 비율 | 20% 이하 | AI 판정 / 전체 후보 |
| AI 실패 후 자동 처리 | 0건 | AI 실패 시 자동 포함·제외 없음 |

## 12. 운영 및 모니터링 계획

### 12-1. 운영 통계 (일별·주별)

**소스 관련:**
- 소스별 실행 횟수
- 소스별 성공·부분실패·실패 건수
- 소스별 수집 공고 수
- 소스별 고유공고 기여 건수
- 소스별 중복 비율

**매칭 관련:**
- 행정성 제외 건수
- 사이트 내부 중복 건수
- 사이트 간 중복 건수
- 수정·연장공고 감지 건수
- 예비창업 대상 불일치 건수
- 교육·멘토링·투자 단독 제외 건수
- 지역 제외 건수
- 마감 제외 건수

**판정 관련:**
- 규칙 자동 포함 건수
- 규칙 자동 제외 건수
- AI 검토 건수
- AI 포함·제외·실패 건수
- 사람확인 건수

**발송 관련:**
- 최종 발송 건수
- 중요 변경 재발송 건수

### 12-2. 소스 정리 기준

소스별 고유공고 기여도가 지속적으로 낮고 중복률이 높은 경우 비활성 후보로 지정:

```
고유공고 기여도 = 해당 소스에서만 발견된 공고 수 / 해당 소스 전체 수집 수
중복률 = 1 - 고유공고 기여도

기준: 최근 30일간 고유공고 기여도 < 5% AND 중복률 > 95% → 비활성 후보
```
